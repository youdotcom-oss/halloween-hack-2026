3.1 CrewAI — the swarm

Onboarding: start from the official quickstart — https://docs.crewai.com/v1.13.0/en/quickstart. The commands below are the local equivalent for this page.

The quickstart every team is expected to start from:

crewai create crew scaffolds YAML agents and tasks; npx skills add crewaiinc/skills gives your coding agent the framework's own conventions. CrewAI needs Python ≥ 3.10 and < 3.14 — check with python3 --version before you debug anything else.

3.2 You.com — the grounding

Onboarding: go to https://you.com/home and sign up — you get a starter credit when you do. Create your API key there and put it in .env as YDC_API_KEY. If you run low, ask the You.com folks at the organizers' table and they'll top you up — don't let credits stop your build.

One key, two grounding endpoints. Both authenticate with X-API-Key, not a bearer token:

Search takes a natural-language query and up to count: 100 results. Snippets come back by default; add extraction: "highlights" to get the passages that actually answer the query instead of whole pages, which is what keeps a swarm's context small enough to think in.

3.3 Parasail — the second brain

OpenAI-compatible at https://api.parasail.io/v1, with its own key and credits issued by Parasail. Their event instructions live at Parasail's event instructions — the deck covers claiming the key and what the credits cover.

PurposeModel IDInput / Output per 1M

Three capabilities decide your architecture:

  • Streaming. stream: true returns SSE, which is what makes a generated interface appear while the model is still thinking — Track 2 runs on this.

  • Server-enforced JSON. response_format with a json_schema constrains decoding, so the Haunted Dashboard's manifest is shape-valid rather than prompt-hoped.

  • Embeddings. POST /v1/embeddings for cluster-this-reading or retrieve-this-lore steps; that is the Track 1 vector step.

  • Rate limits bite loops: 5 RPM free, 500 RPM paid, unlimited enterprise. A while True on a free key starves your own table.

  • The Responses API requires store: false on every request.5 Multi-turn and tool calling work; server-side state does not exist, and omitting the flag errors.

  • extra_body.guided_json is the second path to schema-locked output, alongside response_format.

4. Track 1 — The Exorcism Protocol

The brief

A paranormal outbreak is spreading through a live facility simulation. Build a supervised swarm — agents with distinct roles, distinct tools, and only partial individual knowledge — that senses, shares intel, and coordinates containment in real time.

Victory belongs to the swarm, not to a single model. Containment speed, false-alarm rate, and civilians saved feed the venue scoreboard.

Pull a tick

Ticks come from the scenario feed on your card, not from a shared proxy. Connect it as an MCP server and the swarm gets the incident as a tool call:

from crewai.mcp import MCPServerHTTP

scenario = MCPServerHTTP(
    url=os.environ["SCENARIO_MCP"],
    streamable=True,
    headers={},
)
# tools: hack26-get-tick, hack26-submit-containment, hack26-get-scoreboard

Use MCPServerHTTP, not the "https://..." string shorthand: inside a running event loop the shorthand resolves to zero tools with no error, which is an hour you will not get back.

Input contract, per tick

{
  "tick_id": 142,
  "facility_id": "aws-builder-loft-sf",
  "sector_reports": [
    {
      "sector": "catering_coffee_bar",
      "sensors": { "emf_milligauss": 98, "temp_c": -4, "motion_events": 17 },
      "sighting": { "entity_class": "level-5-phantom", "confidence": 0.82, "witness_count": 4 },
      "civilian_status": "4 pinned",
      "containment_state": "breached"
    }
  ],
  "swarm_budget": { "max_active_agents": 8, "api_credits_remaining": 45000 },
  "escalation_channel": { "app": "discord", "channel": "#loft-incident", "via": "one-mcp" }
}

Fields are fixed: do not rename sector_reports, civilian_status, or containment_state, and do not assume a tick has only one sector. swarm_budget is a budget, not decoration — exceeding max_active_agents is a scored failure.

escalation_channel.app is discord for this venue, and the channel is #loft-incident = 1564842098740695100. Posting there is how the room sees your swarm work; it is also the evidence judges look at when your demo is over.

Report the decision

# call the scenario feed's tool with your self-chosen team handle
decision = await scenario_tools.submit_containment(
    team="team-04", tick_id=tick.tick_id, action="evacuate"   # contain | evacuate | observe
)

You get a judgment back immediately: the action the tick called for, a 0–1 score, and whether it counted as a false alarm. The scoreboard updates on every submission, so you can see where you stand without asking a judge.

5. Track 2 — The Haunted Dashboard

Track 2 has no live feed. Work from the published fixture files — start with fixtures/haunted-dashboard.json. The source files also live in the event repo at https://github.com/youdotcom-oss/halloween-hack-2026/tree/main/fixtures. The brief

Build a Spooky Tactical Command Station. Take unstructured incident logs and compile a functional interface from them, live, over a WebSocket — not a template filled with strings, but components chosen and ordered by the model, then rendered.

You can build beyond the fixture. The supplied incident is a starting point, not the scope ceiling. Add your own incident streams, sectors, entity types, components, interactions, live updates, timelines, maps, or replay modes when they make the command station better. Track 2 is more open-ended technically than Track 1 — you are not locked to a fixed tick, action set, or scoreboard — but less open than Track 3, because the core problem is still prescribed: turn unstructured incident logs into a functional interface. Track 3 is where you define the problem itself.

The pipeline that wins

An ingestion Flow routes on incident class, retrieves against an indexed store of blueprints or lore counters, and emits a schema-locked manifest. Grounding comes from You.com. Inference comes from Parasail, streamed so the interface appears while the model is still thinking. And the command station has to be operable: its dispatch control posts to the same #loft-incident channel as Track 1.

A manifest that is valid JSON but an unusable interface loses to an uglier one a judge can actually operate.

6. Track 3 — The Open Haunt

Do what you want. Track 3 is for teams who would rather bring their own problem than fit either prescribed track. Build any project that puts the partners to work in a way neither track asks for — a different kind of agent, a tool other builders would use, a workflow nobody here has thought of — and it gets judged on the same criteria as Track 2 (see §8): innovation & originality, technical implementation, user experience, impact & relevance, presentation & documentation.

There are no mandatory themes, schemas, fixtures, live feeds, or scoreboards in this category. Work from first principles:

  1. Pick a real problem someone in this room (or outside it) actually has.
  2. Decide which partners are load-bearing — at minimum, make one partner impossible to remove without the project collapsing.
  3. Build the smallest thing that proves the idea works end to end.
  4. Submit through the same Google Form as everyone else.

Constraints that still apply:

  • You still need working credentials and a reproducible repo (one command to run it).
  • Partner usage still counts: a partner used only as a passthrough earns nothing.
  • Hardcoded demo responses, fake live data presented as real, and a static mockup dressed as an agent will score poor on technical implementation regardless of how good the framing is.
  • Keep API keys in .env, never in the repo. Submitted projects are auto-reviewed and judged live, same as the other categories.

If you're torn between The Open Haunt and a prescribed track, pick the track — its guardrails help more than they constrain. Choose The Open Haunt when the idea simply doesn't fit either brief.

8. How you are scored

Your track's rubric governs. Track 1 is scored by the scenario feed against containment decisions. Track 2 and Track 3 are scored by judges' criteria. Partner usage and reproducible code matter in all three.

Track 1 — Exorcism Protocol (feed-scored, 100 pts)

CriterionPtsWhat it measures
Containment speed vs. baseline30Ticks to resolve the injected scenario, against a reference run
False-alarm rate20Escalations that fire on a harmless control tick
Civilians saved / escalation correctness20Right action, right channel, no over-escalation
All four partners genuinely used20CrewAI swarm, You.com grounding, Discord webhook dispatch, Parasail inference — each irreplaceable

Tie-break: fastest clean run from tick to scoreboard update.

Disqualifiers: a single-agent "swarm"; hardcoded scenario responses; a partner used only as a passthrough.

How the numbers are produced: the scenario feed judges every containment submission. A referee decides which action the tick called for — Jev when the feed's key is configured, otherwise a fixed rule — and the scoring curve is constant: correct 1, contain-versus-evacuate 0.5, observing a breach 0. Acting on a control tick is recorded as a false alarm. Because the curve is fixed, two teams facing the same tick face the same arithmetic. A final judge still watches your demo: passing the feed does not excuse a swarm that cannot explain itself.

10. When the network dies

The scenario feed is the only shared service on your path. It holds your cursor, your judgments, and the scoreboard — everything else (You.com, Parasail, One, CrewAI) talks to the internet directly with your own credentials.

If the feed is unreachable:

  1. Keep building. The ticks are published next to this page as plain JSON — fixtures/outbreak-level-5.json and fixtures/control-tick.json — the same documents the feed serves. Point your swarm at the file instead of the tool call and nothing else changes; the field names are identical, which is why §4's contract is printed in full.
  2. Queue your submissions. Compute the decision, log it with its tick id, and replay it to hack26-submit-containment when the feed returns. A late submission still counts; the tick is what matters, not the wall clock.
  3. Escalate by hand if the threshold is real. Posting to #loft-incident yourself is a legitimate demo, and judges will see it. Use the invite (https://discord.gg/f3Qz4gza) and event role; or, if you need a programmatic path, use the venue webhook (https://discord.com/api/webhooks/1564863196202934376/rJr-P0-a9FWnsehNckLK_i-HnTMxdzp8SffZIqRjEWEGEE81VbN03DEyDKddxqEcgjOD).

The organizers keep a local sandbox for verifying this page, but it is not part of your setup and you do not need it: there is no proxy to stand in for, and no client code of ours that you have to run.
